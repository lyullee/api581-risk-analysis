# Python 라이브러리 설계

2026-10-24 사용자 요구에 따라 import 기반 라이브러리로 정리했다.
GitHub/PyPI 배포 및 slabx 계열과의 깊은 결합을 목표로 한다.

## 공개 경계

`api581.api.<domain>.<function>(inputs: Input, *, context: Context | None) -> CalculationResult[Output]`

계산마다 이름 있는 함수·입력 모델·출력 모델을 제공한다. 함수 시그니처와 결과 타입은 일반 Python
소스에 명시하여 자동완성·타입 분석·호출부 탐색이 가능하다. 509개 계산을 19개 분야로 나눈다. 디지털 트윈은 단일 요청과 입력 순서를 보존하는 serial/thread/process batch 실행 경계를 함께 제공한다. `api581.review_queue()`와 `api581.calculation_evidence()`는 표준 절을 계산과 양방향으로 연결해 외부 품질관리와 배포 파이프라인이 근거 큐를 직접 소비할 수 있게 한다.
최상위의 기존 `release`, `effects`, `pof` 등은 계산 구현 모듈이며, 신규 소비자의 공개 진입점은 `api581.api`다.

`api581.api.risk.portfolio()`는 여러 컴포넌트의 사전 검증된 위험 기여를 합산하고, 전체 합계와 함께 `component_contributions`를 반환해 디지털 트윈의 원인·기여 추적을 보존한다.

`api581.validation_queue()`는 계산별 검증 수준과 제한사항을 일괄 반환하며, `domain`, `validation_level`, `direct_test` 필터로 분야와 native/software 및 직접/간접 테스트 근거를 분리할 수 있다.
`api581.coverage_summary()`의 `validation_by_domain`은 분야별 native fixture/software-only 및 직접 테스트 참조 수를 함께 제공한다.
같은 summary의 `scope_status_counts`는 Part/Annex별 절 상태(partial/not_implemented)를 제공한다.
`api581.clause_evidence()`는 절별 연결 계산 수, native/software 분류, 직접 테스트 모듈 수를 함께 반환한다.
`api581.scope_boundaries()`는 외부 표준/API 또는 native engine 범위 밖의 명시적 미구현 경계를 별도 조회한다.
`api581.standard.sections(scope=..., status=..., review_category=...)`는 Part/Annex 범위별 절 검토 큐를 typed 형태로 반환한다. `api581.standard.documentary_coverage()`는 Part 1의 References/Definitions/Acronyms처럼 원문 메타데이터가 추출된 절과, 추가 서술 검토가 남은 절을 별도 목록으로 반환한다. 메타데이터 추출은 계산 절의 완전한 해석을 의미하지 않는다.
동일한 문서 근거 요약은 `api581.coverage_summary()["documentary_coverage"]`에서도 통합 조회할 수 있다.
같은 요약의 `reference_fixture_count`는 public registry로 재실행 가능한 독립 산술 fixture 수를 표시한다.
디지털 트윈 응답은 같은 수준을 `validation_level`로 내장하므로 consumer가 catalog 재조회 없이 provenance를 저장할 수 있다.
응답의 `software_test_modules`는 해당 계산 ID를 직접 참조하는 테스트 모듈 manifest 경로를 보존하며, native fixture 목록과 구분된다.
설치된 소비자는 `api581.evidence.software_test_evidence()`와 `calculation_test_modules()`로 동일 근거를 패키지 내부에서 조회할 수 있다.
실행 가능한 shard 제출 예시는 `examples/digital_twin_hpc_batch.py`에 있으며, scheduler/transport 없이 plan 검증·shard 실행·응답 병합을 재현한다.

| 계층 | 위치 | 책임 |
|---|---|---|
| 공개 함수 | `src/api581/api/` | 분야별 입력·결과 타입과 호출 함수 |
| 실행 경계 | `core.py`, `result.py` | 검증·수치 오류·출처·재현성·타입 있는 결과 |
| 계산 구현 | `release.py`, `effects.py`, `thinning.py` 등 | 순수 계산식 및 표 조회 |
| 결과 모델 | `outputs.py` | 정적 출력 클래스 및 ID 매핑 |
| 발견·조합 | `catalog.py`, `workflow.py` | 스키마/출처 조회, 이전 계산 출력 연결 |
| 통합 경계 | `dispersion.py`, `slabx_adapter.py`, `_slabx_worker.py`, `digital_twin.py` | 일반 시간 프로파일 계약 초안, 격리된 SLABx 호출, 디지털 트윈 요청·결과 envelope |
| 선택 저장 | `storage.py` | 호스트가 명시적으로 생성하는 SQLite 저장소 |

입출력 검증은 Pydantic 2를 사용한다. 공개 결과는 `.outputs`로 값을,
`.references`와 `.limitations`로 계산 근거와 제한사항을 확인한다.
배치 도구는 `evaluate(id, inputs, context)`의 dict 결과를 사용할 수 있다.

## 조합과 오류

일반 Python 코드에서 앞 함수 결과를 뒤 함수 입력에 전달하는 방식이 기본이다.
선언형 워크플로는 Python 데이터 모델이며 앞 단계의 `outputs`만 참조할 수 있다.
실패한 조합에는 성공 결과가 반환되지 않는다. 단계별 계산은 외부 I/O를 하지 않는다.

입력 오류는 `ValidationError`, 지원하지 않는 조건은 `DomainError`로 구별한다.
판본·단위·재질·누출 상태 등 적용 범위가 불명확하면 기본값으로 채워 계산하지 않는다.
공학적 근사와 원문 불일치는 계산 메타데이터에 남긴다.

`Context`는 호스트의 설비·부품·관측시각·입력 리비전과 연결한다.
해시는 정규화한 입력·문맥·계산 ID·패키지 버전·코드 지문에서 만들며 실행 UUID·실행 시각과 분리한다.
코드 지문은 패키지의 하위 디렉터리까지 포함한 Python 소스에 기반한다.

## Digital twin exchange contract

`api581.digital_twin.TwinCalculationRequest`는 transport-independent 요청 envelope다. 설비·부품·관측시각·상관 ID·source revision·측정값의 단위/품질/불확실성을 보존하고, `to_context()`로 기존 계산 경계에 연결한다. `TwinCalculationResponse.from_result()`는 계산 결과의 run ID, 입력 hash, 표준 판본, 코드 지문, 참조·제한사항·검증 상태를 잃지 않고 반환한다. 이 계약은 이벤트 버스나 데이터베이스를 직접 호출하지 않으며, naive timestamp·중복 measurement ID·계산 ID 불일치를 거부한다. 로컬 호스트는 `api581.digital_twin.execute_request(request)`로 동일한 registry/evaluate 경계를 거칠 수 있으며, 네트워크 재시도·인증·저장은 호스트 책임으로 남는다.
계산 결과와 twin response에는 `direct_public_test_modules`도 포함되어 공개 `evaluate()` 경계를 실제 호출한 검증 모듈을 배포 환경까지 전달한다.

`examples/digital_twin_risk_assessment.py`는 damage mechanism 조합→GFF/FMS→네 개 hole consequence→risk 결과를 동일한 twin envelope로 실행하는 재현 예제다.

## 새 계산 추가

1. 계산 구현에 입력 모델, 순수 함수, `@calculation` 출처·적용 제한을 추가한다.
2. `contracts.py`의 `SPECS`에 출력 필드와 타입을 추가한다.
3. `scripts/build_python_api.py`로 정적 출력 모델과 공개 함수를 재생성한다.
4. 수치 기준·경계·물리 불변량·적용성 오류 테스트를 작성한다.
5. `scripts/export_contracts.py`로 목록과 JSON Schema를 갱신한다.
6. 원문 조항 인벤토리의 부분 구현 연결을 갱신한다.

생성기는 개발 도구다. 패키지 소비자는 코드 생성 없이 wheel의 정적 Python 파일을 사용한다.
등록된 ID·공개 함수·출력 타입의 대응은 테스트로 검증한다.

## 배포 및 연동

`src` 패키지 구조, setuptools wheel, `py.typed`, 문서화한 공개 함수를 사용한다.
HTTP 서버·UI·인증·이벤트 버스·클라우드 배포는 이 라이브러리 범위에 포함하지 않는다.
일반 시간 프로파일 계약은 초안이다. 별도의 `api581.api.dispersion.native_pool_centreline`은
SLABx1.0.8/SLABx-LH2 0.2.0의 실제 지면 증발 풀 API를 프로세스 격리하여 실행한다.
선택 의존성이 없거나 버전이 다르면 실패하며 결과를 대체 생성하지 않는다. 중심선 거리에서 피해면적을 만들지 않는다.
별도 `native_pool_footprint`는 실제 횡방향 농도장에서 표본 삼각형 보간 면적을 계산하고,
`native_pool_flash_fire`는 유효한 LFL 면적만 플래시화재에 연결한다. 경계 검열·LH2 전제 위반은 면적 사용을 차단한다.
향후 어댑터는 원시 엔진 응답을 검증한 계약으로 변환하고 단위·버전·회귀 사례를 추적한다.
릴리스 전에는 호환성 정책, 라이선스, 배포할 표준 기반 데이터의 범위를 확정한다.

## PRD·번들 계산 경계

PRD는 설계·환경 수정 eta와 검사 갱신 eta, Weibull 누적확률, 사건 압력 보정,
요구빈도와 보호설비 LOC를 각각 독립 함수로 제공한다. 원문 검사 갱신의 방향 제한과
1년 미만 검사 무효 조건을 적용한다. 정비·설계 변경에 따른 이력 유효성과 기준일은 호스트가 판단한다.

번들은 통계 점 추정과 비용/검사 계획을 분리한다. 고정 beta에 대한 eta 갱신은 관측된 실패뿐 아니라
중도절단 노출시간도 합산한다. 추가 예측 수명점은 실패 수에도 포함한다.
교체 최적화는 원문의 우측 구간 끝점 적분을 따르며 탐색 범위 내 최적값과 경계 여부를 반환한다.
수식의 차원과 원문 명칭이 다른 경우 실제 계산 기준을 출력 필드와 제한사항에 명시한다.

중첩 요청 모델도 생성된 공개 분야 모듈에 `*Input` 별칭으로 노출한다.
예제와 호스트 통합은 계산 구현 모듈을 직접 import할 필요가 없다.

## PRD 누설·복수 장치·통합 위험

누설 피해는 Part1 본문식과 표7.15의 불일치를 입력의 명시적 모델 선택으로 추적한다.
SI kg/s·초 단위를 사용하며 원문의 시간당 유량×24×일 환산을 중복 적용하지 않는다.
회수 계수는 재고 손실 비용에만 적용한다. 단순 누설량과 비용 등가 손실 질량을 구분한다.

복수 장치 압력 저감은 max(.25,sqrt(A/Atotal))을 따르며 PRD POFOD 압력 보정용 원 압력을 함께 반환한다.
FAIL 위험은 사건을 먼저 합산한 설비별 값에서 최댓값을 선택한다.
누설 위험의 확률/빈도 차원을 명시적으로 선언하여, 원문 단순 합산 지수와 연간 위험도를 구분한다.

서비스 날짜 계산은 설치·검사·정비·교체·설계 변경을 구분한다. 정비는 연수를 재설정하고,
교체/설계 변경은 이전 통계 이력의 유효성을 제한한다. 전체 eta 이력 자동 재계산은 별도 미구현 범위다.

## Type1·독성 COF 확장

Type0와 Type1의 공개 계산을 구분하고 공통 소스/검지/차단/재고 계산은 `release.controlled_scenario`로 공유한다.
기존 Type0 함수 입력과 결과 계약은 유지했다. Type1은 명시적으로 선택한 AINL/AIL 셀을 사용하고
연속/순간·AIT의 추가 보간을 수행하지 않는다. 출력이 한쪽만 정의된 경우 단일 설비/인체 함수로 조회할 수 있다.

HF/H2S는 미국 단위 log10 상관식을 Annex 환산 상수로 SI에 연결한다.
추가10종 독성은 별도 SI 표4.13M을 직접 사용한다. 시간 보간은 피해면적 사이에서 수행한다.
연속 누출률과 순간 질량, 독성 이론 누출률과 가연성 보정 누출률을 구별한다.
원문 HF 순간 절편 해석이 필요한 경우 명시적 값과 근거를 입력에 보존한다.

단일 독성 성분 계산은 분율·시간·완화·스크리닝과 해당 상관식으로 이어진다.
여러 독성 성분은 최대 면적으로, 네 누출공은 기구별 빈도 가중 후 최댓값으로 집계한다.
H2S 예제는 기존 재정피해 및 위험 함수까지 실제 Python 조합으로 연결한다.

## 풀화재 형상·복사 경계

단계별 독립 함수와 통합 함수는 같은 구현을 사용한다. 에너지 W와 표면 방사열 W/m²,
공기 밀도와 증기 밀도, 표면 거리와 축 거리를 별도 값으로 다룬다.
형상계수의 인쇄식과 기하 대조식은 명시적 선택지로 유지하며 자동 대체하지 않는다.
원문의 Y 거리 해석도 호출자가 선택하고 결과에 보존한다.

임계 거리 반복은 명시한 외부 계산 영역과 최대 거리 안에서 수행한다.
브래킷 실패·반복 실패·비물리적 형상계수는 구조화한 오류로 반환한다.
외부 영역 시작점에서 한계 이하인 경우에는 교차점 대신 경계 상태를 반환한다.
독립 중점 표면 적분과 대조한 검증 코드는 런타임 의존성을 추가하지 않도록 테스트에만 둔다.

## 파열 폭발·NFNT 조합

물리폭발/액체 BLEVE의 에너지·TNT 환산은 서로 다른 함수와 계수를 쓴다.
BLEVE 통합 계산은 동일 파열/대기 압력에서 액체 플래시분과 기존 증기 공간의 TNT 등가량을 더한다.
공통 폭압 곡선·구간 검사·확률 기준 압력·거리 역산은 `blast.py`를 재사용한다.
파열 잠재량과 현재 누출공의 사건 등가량을 다른 출력 필드로 구분하여
작은 누출에서도 저장 에너지가 사라진 것처럼 해석하지 않도록 한다.

`consequence.level2_nfnt_case`는 사건 조건부 면적에서 최대 선택 후 비점화 확률을 한 번 적용한다.
네 누출공의 GFF 평균과 실제 DF/Fms 보정 빈도를 사용하는 연간 위험도를 별도 함수로 연결한다.
NFNT 전용 집계에 화재·독성 면적을 자동으로 합산하지 않는다.

## Level2 독성 농도 이력 경계

`toxic_level2.py`는 Table4.14의 역사적 기준 조회와 종별 노출 계산을 담당한다.
농도 이력의 입력은 종별 ppm·시간 초이며, 공급 엔진/측정/파일의 근거를 `profile_source`에 기록한다.
슬랩 계열 엔진의 실제 출력 스키마가 확정되지 않은 상태에서 이 입력을 엔진의 네이티브 출력으로 주장하지 않는다.

원문 상수 농도 probit와 시간 적분 확장의 `method_origin`을 구분한다.
적분은 이전 값 유지/선형 농도 보간을 명시적으로 선택한다. 농도의 거듭제곱을 적분하므로
농도 평균값에 단순히 지수를 적용하지 않는다.
전체 혼합물 농도장에 대한 독성 몰분율 보정과 종별 농도장을 구분한다.
피해면적 후처리는 선택한 기준의 성분별 면적만 받아 성분 최대·비점화 확률·GFF를 단계별로 적용한다.

## Level2 평가 조합

`api581.api.level2`는 Level1과 다른 최종 결합식을 분리한다.
원래 사건면적→사건 확률/비점화 가중→기구별 GFF 평균→가연성 기여와 비점화 최대의 합 순서다.
공통 시나리오 모델은 하나의 비점화 확률을 공유해 독성·NFNT의 확률 기준이 달라지는 것을 막는다.
독성 경로 생략은 `not_applicable`과 근거가 필요하다.

종합 평가는 부품형식의 GFF로 네 누출공을 가중하고 같은 부품형식의 수리·정지기간 표를 사용한다.
면적은 계산 결과만 재정 모델에 전달하며 사용자 재정 입력에는 피해면적 필드를 두지 않는다.
계산 범위는 `supplied_level2_event_probabilities_areas_and_damage`로 표시한다.
공통 DF/Fms의 부품 위험 계산이며 누출공별 DF나 자동 손상 적용성·확산 실행을 포함하지 않는다.

## 미점화 풀 소스항의 지원 조건

`evaporation.py`는 화재 연소율과 분리한 미점화 풀의 증발 식을 제공한다.
독립 원문식과 정상상태 역산/지원 조건을 서로 다른 계산 ID로 관리한다.
풀 표면의 증기 체적유량·정상 도달시간을 일반적인 액체 유입 체적유량·임의 경과시간으로 대체하지 않는다.

`vapor_source_rate_kg_s`는 정상상태의 공급시간·면적 조건을 지원하는 경우에만 제공한다.
실패한 평형은 원래 평형 유량·반경과 제한 상태를 남기며 사용 가능 유량은None이다.
이는 엔진의 확산 입력에 지원되지 않는 평형 소스가 조용히 들어가는 것을 막기 위한 계약이다.
시간별 풀 성장·배수·질량수지·플래시는 별도 미구현 범위다.

## 방출상과 액적 분할 기준

`source_partition.py`는 방출구 상 판정과 플래시 후 증기/액체 분배를 구별한다.
포화압의 중복/누락 경계는 자동 분기하지 않고 rate 계산에서 근거 있는 상 선택을 받는다.
2상 rate는 보수적 액체식이라는 `rate_method`를 출력한다.

액적 동반율은 인쇄식과 `post_flash_mass_balance`를 명시적으로 구분한다.
후자는 입력한 플래시 후 전체 증기 분율을 사용하며 임의 EOS 결과나 공인 정오표를 뜻하지 않는다.
풀/제트/증기/액적 출력은 모두 같은 가중 후 방출량 기준이며 선택 근거를 입력에 보존한다.
제트의 총 질량유량과 제트 내부 증기 분율은 별도 값으로 확산 요청 초안에 전달한다.
풀 유입은 별도 증발 모델로 연결하며 두 소스의 위치·온도를 조용히 합치지 않는다.

## 점화와 그림 사건 트리

`ignition.py`는 가연성 상별 유량·상온 점화식·AIT 한계·온도 보간·조건부 표를 분리한다.
온도 기준의 원문/사용자 해석과2상 가중 기준은 계산 입력·제한사항·코드 지문에 남긴다.
단일상 조합은 그림의 VCE/플래시 경로를 따르며 비점화 분기를 무조건 안전으로 부르지 않는다.
그림5.3 순간 누설 파이어볼은 영역 선택을 명시해야 면적 집계에 사용할 수 있다.
기존 기본 파열 전용 정책은 유지한다.
2상 트리는 `two_phase_events.py`에서 같은 온도 기준·상별 물성·가중 선택을 재사용한다.
상관된max(jet,pool)은 별도 면적 모델로 한 분기 확률을 공유한다.
기존5개 사건 입력의 형태는 유지하고 선택적 `correlated_jet_pool` 필드를 추가했다.
이 필드가 있으면 별도 jet/pool의 확률과 면적은0이어야 한다.
연속 파열·현장/LH2 확률 검증과 실제 유체/EOS 연결은 후속 범위다.

## 대기압 저장탱크 경계

`api581.api.tank`는 AST 바닥·쉘의 원문 단위와 일반 압력설비 소스를 구별한다.
수리전도도는m/day,토양 표는cm/s,유동식의 내부 지름은mm,원문 rate는bbl/day다.
원문 결과를 먼저 계산하고 명시한 C13으로m³/s·kg/s에 연결한다.
탱크 전용 검지시간·재고를 사용하며 일반 검지/차단 감소계수를 자동 적용하지 않는다.

전이구간의 누출공 배율·검지 경계·기초/RPB 우선순위는 명시한 입력 기준을 보존한다.
탱크 파열의 전체 재고 유출량은 시간None을 반환하고 압력설비의 순간 파열로 자동 변환하지 않는다.
AST GFF 및 환경·재정 피해는 전용 tank API에서 계산한다. 바닥 통합과 쉘의 외부 사건 면적 기반 통합을 제공한다.

## 실제 제트 경계

NativeJetGeometry는 팽창을 확인한 대기압 형상·상태·조건을 받는다.

source_temperature_clamped와 native_near_field_status에 실제 온도 처리와 미재구성 근접장을 기록한다.

2016 기준 선택은 제공된 후보와 활성화한 표에 한정한다. 상위 후보 제외와 같은 우선순위 선택은 명시한다.
